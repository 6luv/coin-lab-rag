## 3. 요구사항 F2001 ~ F2012 대응 설계

### F2001 항목 메타데이터 적재
- 로드: `data/coins.json` (CoinGecko markets + 상세 + 위키 매핑을 `items.normalize` 로 정규화)
- 색인 텍스트(`items.index_text`): `코인: 이름(심볼) / 한국어 이름 / 시가총액 순위(기준일) / 카테고리 / 해시 알고리즘 / 출시일 / 발행 플랫폼 / 설명(한국어 우선, 600자)`
- 가격·등락률은 매일 바뀌어 의미 검색에 맞지 않으므로 **텍스트에서 제외, 메타데이터로만** 보관 (화면 표시용, 기준 시각 함께 표시)
- 검증: `python -m scripts.check_sample` → 항목 수 ≥100, 필수 필드, 텍스트 예시 출력

### F2002 메타데이터 색인 (RAG 1)
- 컬렉션 `coin_meta`, 코인 1건 = 청크 1개, **chunk id = coin_id** → 재실행 시 덮어쓰기(건수 불변)
- 메타데이터: coin_id, symbol, name, name_ko, market_cap_rank, categories, genesis_date, source_type=`coin_meta`, url(CoinGecko 페이지), snapshot_at
- 화면 사이드바에 색인 건수 상시 표시 (`/api/status`)

### F2003 검색어 추출 (프롬프트1)
- 역할: "너는 가상자산 프로젝트 리서처다"
- 입력: 코인 이름·심볼·카테고리 + 사용자 질문 → 출력: **JSON 배열만** (`["이더리움 더 머지", "지분증명"]`)
- 항목 자체 문서 검색어(위키 제목 또는 코인 이름)는 프롬프트 결과와 무관하게 **항상 첫 번째**로 추가
- 파싱 실패 시 `코인 이름 + 질문 앞부분`으로 대체, LLM 호출 실패 시 수집만 건너뛰고 기존 문서로 답변
- 위키 연결 문서가 없는 코인(110개)은 `코인 이름 암호화폐`를 첫 검색어로 추가 (동명이인 문서는 프롬프트2가 거름)

### F2004 외부 문서 수집 (프롬프트2)
- 출처 우선순위: 한국어 위키백과 → 영어 위키백과 → 백서(PDF, F2016)
- 검색어마다 후보(제목·요약 snippet)만 모아 프롬프트2로 선별 → 선택된 것만 본문 수집
- **항목 자체 문서(위키데이터로 연결된 문서)는 선별·길이 규칙보다 우선해 항상 색인** (`is_item_doc=true`)
- 원문 출처: 위키는 URL, PDF 는 파일명+쪽
- 재수집 방지: `data/docs/manifest.json` 에 코인별 검색 키워드 기록 (NF2002). 수집·색인이 모두 성공한 검색어만 기록 (D10)
- 호출 제한 환경: `data/docs/` 의 수집 묶음을 그대로 읽어 대체 가능 (명세 허용)

### F2005 외부 문서 색인 (RAG 2)
- 컬렉션 `coin_docs` (메타데이터와 분리), RecursiveCharacterTextSplitter
- 시작값 **청크 1,000자 / 중복 200자** (`config/settings.json`, 환경변수 `CHUNK_SIZE`/`CHUNK_OVERLAP`로 비교 실험)
- **chunk id = `{coin_id}:{doc_id}:{순번}`**, doc_id = `{source_type}-{page_id}` → 여러 코인이 같은 문서를 모아도 충돌 없음
- 청크 메타데이터: title, url, source(출처명), source_type, coin_id, related_coin, search_query, is_item_doc, collected_at
- 재색인 시 새 청크를 먼저 넣고 남는 이전 청크만 지움 → 잔여 청크 없음, 임베딩 실패 시 기존 색인 유지 (D10)

### F2006 근거 검색 및 병합
- 선택 코인의 `coin_meta` 청크는 **검색 없이 항상 근거 1번**
- `coin_docs` 는 `where={"coin_id": 선택 코인}` 필터 + 질문 유사도 Top-k (`retrieval.top_k`, 기본 6)
- 병합 후 (문서, 청크 순번) 기준 중복 제거, 문서는 관련도 순·같은 문서 안은 청크 순서로 정렬
- `search_type`: `similarity` | `mmr` 만 허용 (그 외 값은 오류)

### F2007 근거 기반 답변 (프롬프트3, LangGraph)
- 그래프: `retrieve` → `generate` 두 노드 (StateGraph, state = question, coin_id, contexts, answer)
- 프롬프트3: "제공된 근거만 사용, 근거 번호 `[근거 n]` 표기, 근거에 없으면 '제공된 문서에서 확인되지 않습니다', 가격 예측·매수/매도 권유 금지"
- 근거마다 출처 유형 라벨: `CoinGecko 메타데이터` / `한국어 위키백과` / `English Wikipedia` / `백서 PDF`

### F2008 근거 표시
- 답변 본문에서 `[근거 n]` 정규식 추출 → 실제 인용된 근거만 `sources` 로 반환, `cited` 플래그
- 화면: 제목 + 출처 배지 + 원문 링크(PDF는 쪽), 인용 0건이면 "답변에 인용된 근거가 없습니다" (web/app.js 구현 완료)

### F2009 항목 선택 및 질의응답
- 왼쪽 "코인 검색" 입력창(이름·심볼·한글명으로 목록 거르기), 코인별 대화 기록 분리 저장(localStorage `coinlab.histories`)
- `?coin=<coin_id>` 공유 링크

### F2010 도메인 특화 기능 (2개)
1. **프로젝트 리스크 브리핑**: 합의 방식·발행량 구조·주요 사건(해킹·네트워크 중단·규제)·중앙화 요소를 항목별로 정리, 각 항목에 근거 번호. 문서에 없는 항목은 "문서로 확인 불가"로 표기
2. **주장 팩트체크**: 사용자가 입력한 주장(예: "도지코인은 발행량 상한이 있다")을 근거와 대조해 `사실/사실 아님/문서로 확인 불가` 판정 + 근거
- 이유: 가상자산은 과장·오해가 많은 도메인이라 "근거로 검증"이 가장 가치 있는 기능

### F2011 조건 기반 항목 탐색
- 자연어 조건 → `coin_meta` 유사도 검색 후보 20건(`recommend_candidates`) → LLM이 조건 충족 코인만 선별·이유 작성 → 카드 → 클릭 시 해당 코인 대화
- 서버 없는 샘플 모드에서는 키워드 일치 필터로 동작하며 그 사실을 화면에 표시

### F2012 진행 상태 및 안내
- 진행 상태: "문서를 확인 중 → 문서 n건 추가(제목) → 답변 생성 중" 단계별 표시 (구현 완료)
- 안내: GMS 키 누락, 코인 색인 0건, 문서 색인 0건, 서버 미연결(샘플 모드)
- **면책**: 하단 고정 바 상시 표시 + 모든 답변 하단 "투자 조언이 아님" (구현 완료)
- 오류는 사용자용 문장만 표시, 키·프롬프트 전문·스택트레이스 비노출 (NF2004)
