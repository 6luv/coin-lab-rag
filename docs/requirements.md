# 요구사항 기준 (검증용)

출처: `AI코어프로젝트_2회차_요구사항정의서.pdf` (SSAFY AI 코어 프로젝트 2회차 명세서 — 2.7 요구사항, 3장 구현 명세, 4장 검증, 6장 프로젝트 결과).
원본 PDF 는 저장소 밖(Claude 프로젝트 파일)에 있으므로, 검증(Codex 등)은 이 문서를 기준으로 삼는다.
명세의 "항목"은 이 프로젝트에서 **코인**이다. 필수 기능은 수정할 수 없고, 도메인에 맞게 표현만 바꿀 수 있다.

- 각 요구사항의 **조건**은 명세 3장, **확인**은 명세 4장 체크리스트에서 옮겼다.
- 검증 결과는 통과 · 실패 · 미확인으로 기록한다 (명세 4장). 실행 결과로 증명하고, 증명이 필요한 항목은 화면을 캡처한다.
- 요구사항 표·구현 위치는 `docs/requirements_definition.md`, 설계는 `docs/rag_pipeline_design.md`, 검증 결과는 `docs/verification.md` 를 본다.

## 0. 전제 조건 (명세 1.2 · 2.1)

| 조건 | 내용 |
|---|---|
| 항목 메타데이터 | 항목마다 이름과 속성을 가진 데이터 약 100건 이상 |
| 외부 문서 출처 | 항목마다 연결되는 설명 문서(한국어 위키백과 권장, 공공데이터·PDF 허용), 출처와 이용 조건 기록. **이 프로젝트의 적용**: 위키(연결·검색) → 백서(PDF·웹) 순으로 확보하고, 둘 다 없는 코인은 CoinGecko 설명만 쓴다(사용자 결정, `docs/decisions.md` D15). 검증 시 이 코인들을 결함으로 보지 않고, 자체 문서가 있는 코인 수만 보고한다 |
| 근거가 필요한 질문 | 근거 없이 답하면 틀리거나 위험한 질문 3개 이상 |
| 위험 도메인 | 건강·금융처럼 조언이 위험하면 전문가 조언을 대신하지 않는다는 안내를 함께 제시 (가상자산 → 해당) |
| 모듈 분리 | 데이터 준비 / Vector Store / RAG 파이프라인 / 서비스 기능 / UI 영역으로 책임 분리 |
| 언어·도구 | Python 3.10+, ChromaDB, (UI) Streamlit 또는 HTML5·CSS3·JavaScript |
| 필수 라이브러리 버전 | LangChain 1.3.14, LangGraph 1.2.10, LangSmith 0.10.17, langchain-core 1.6.0, langchain-openai 1.4.3, langchain-community 0.4.2, langchain-chroma 1.1.0, langchain-text-splitters 1.1.2, ChromaDB 1.5.9, OpenAI 2.54.0, Streamlit 1.62.0, Requests 2.34.2, python-dotenv 1.2.3, typing-extensions 4.16.0 / (심화) fastapi 0.141.1, uvicorn[standard] 0.52.4, pydantic 2.13.5 |

## 1. 기능 요구사항 — 필수 (F2001 ~ F2012)

### F2001 항목 메타데이터 적재 (데이터)
조건
- 선택한 도메인의 항목 메타데이터를 로드한다.
- 항목 1건의 메타데이터를 검색에 사용할 하나의 텍스트로 구성한다.
- 항목은 약 100건 이상이다.

확인
- 로드한 항목 수와 색인된 청크 수가 일치한다.
- 항목 1건의 색인 텍스트를 출력해 의도한 속성이 모두 들어갔는지 본다.

### F2002 메타데이터 색인 — RAG 1 (색인)
조건
- 구성한 텍스트를 임베딩해 Vector DB 컬렉션에 색인한다.
- 색인 결과로 저장된 청크 수를 확인할 수 있다 (화면에 현재 색인 건수 표시 — 명세 예시).
- 색인을 다시 실행해도 같은 항목이 중복 저장되지 않는다.

확인
- 색인 작업을 두 번 실행해도 청크 수가 늘지 않는다.

### F2003 검색어 추출 — 프롬프트 1 (프롬프트)
조건
- 도메인 전문가 역할을 부여한 프롬프트로 외부 문서 검색어를 추출한다.
- 선택한 항목 자체를 다룬 문서는 항상 검색 대상에 포함한다.
- 추출 결과는 파싱 가능한 형식(예: JSON 배열)으로 받는다.

확인
- 하나의 질문에 대해 프롬프트 1 이 뽑은 검색어 목록을 확인한다.

### F2004 외부 문서 수집 — 프롬프트 2 (수집)
조건
- 외부 문서 출처에서 검색해 후보 문서를 모은다.
- 후보 선별 프롬프트(프롬프트 2)로 관련성 높은 문서만 선별해 색인한다 (본문을 받기 전에 버릴 문서를 정해 외부 호출 수를 줄인다).
- 선택한 항목 자체를 다룬 문서는 선별·길이 등 **어떤 제외 규칙보다 우선해 항상 색인**한다.
- 선별된 문서의 본문과 원문 출처(URL 또는 파일명과 쪽)를 수집한다.
- 이미 수집한 검색어는 다시 수집하지 않는다.
- (허용) 외부 호출이 제한되는 환경에서는 제공된 문서 묶음을 읽어 수집 단계를 대신할 수 있다.

확인
- 후보 중 프롬프트 2 에 따라 실제로 색인된 문서와 버려진 문서를 구분해 확인한다.
- 같은 질문을 다시 물었을 때 수집이 다시 일어나지 않는다.
- 선택한 항목 자체를 다룬 문서가 빠지지 않았다.

### F2005 외부 문서 색인 — RAG 2 (색인)
조건
- 수집한 문서 본문을 청크 크기와 중복 길이를 적용해 분할한다.
- 항목 메타데이터와 **분리된 컬렉션**에 색인한다.
- 청크에 문서 제목, 원문 출처, 관련 항목을 함께 저장한다.
- 청크 식별자는 여러 항목이 같은 문서를 수집해도 서로 덮어쓰지 않게 구성한다 (예: `항목 ID:문서 ID:순번`).
- 청크 크기와 중복 길이는 코드가 아니라 설정으로 조정한다.

확인
- 청크 크기 또는 중복 길이를 설정에서 바꿔 색인했을 때 청크 수가 달라진다.

### F2006 근거 검색 및 병합 (검색)
조건
- 선택한 항목의 메타데이터 청크는 항상 근거에 포함한다.
- 질문과의 의미 유사도로 외부 문서 청크를 검색한다 (선택한 항목으로 범위를 좁힌다 — 명세 2.3).
- 두 컬렉션의 결과를 병합하고 중복 청크를 제거한다.
- 근거 수(Top-k)는 설정으로 조정한다.

확인
- Top-k 를 설정에서 바꿨을 때 같은 질문의 근거 목록이 어떻게 달라지는지 확인한다.

### F2007 근거 기반 답변 생성 — 프롬프트 3 (생성)
조건
- LangGraph 를 검색(retrieve)과 생성(generate) 두 노드로 구성한다.
- 프롬프트 3 에 따라 LLM 은 검색된 문서의 내용만 사용한다.
- 근거에 출처 유형(항목 메타데이터 / 외부 문서)을 구분한다.
- 근거가 없으면 추측하지 않고 문서에서 확인되지 않는다고 답한다.

확인
- LangGraph 가 retrieve·generate 두 노드로 구성돼 있다 (그래프 구조 출력 또는 코드 캡처).
- 문서에 없는 것을 물었을 때 추측하지 않고 확인되지 않는다고 답한다.

### F2008 근거 표시 (생성)
조건
- 답변의 주요 주장에 근거 번호를 표시한다.
- 답변에 실제로 사용한(인용한) 근거 문서만 화면에 표시한다.
- 근거 문서의 제목과 원문 출처를 함께 제공한다.
- 인용된 근거가 하나도 없으면 그 사실을 화면에 안내한다.

확인
- 답변 본문의 근거 번호와 화면의 근거 목록이 일치한다.
- 근거 목록에 항목 메타데이터와 외부 문서가 구분돼 표시된다.
- 인용된 근거가 없을 때 그 사실이 화면에 안내된다.

### F2009 항목 선택 및 질의응답 (UI)
조건
- 사용자는 목록에서 질문할 항목을 선택할 수 있다.
- 선택한 항목별로 대화 기록이 구분돼 유지된다.
- 채팅으로 질문과 답변을 주고받는다.

확인
- 항목을 바꿨을 때 이전 대화가 섞이지 않는다.

### F2010 도메인 특화 기능 (서비스)
조건
- 도메인 특성에 맞는 기능을 1개 이상 설계·구현한다.
- 특화 기능도 검색된 문서를 근거로 쓰고, 근거를 함께 제시한다 (문서로 확인되지 않은 내용은 쓰지 않는다).

확인
- 특화 기능의 결과에도 근거가 함께 제시된다.

### F2011 조건 기반 항목 탐색 (서비스)
조건
- 사용자는 원하는 항목의 조건을 자연어로 입력할 수 있다.
- 검색된 후보 중 조건에 맞는 항목만 선별해 제시한다.
- 제시된 항목을 선택하면 그 항목에 대한 질문을 이어갈 수 있다.

확인
- 탐색 결과에 조건과 맞지 않는 항목이 섞이지 않는다.

### F2012 진행 상태 및 안내 (UI)
조건
- 문서 수집과 답변 생성 중 진행 상태를 표시한다 (끝나면 수집된 문서 제목을 함께 보여 준다 — 명세 예시).
- 색인이 없거나 API 키 설정이 누락된 경우 안내를 표시한다 (색인 0건이면 색인 스크립트 실행 안내 — 명세 예시). 검색 결과 없음도 안내한다 (명세 1.3-14).
- 위험 도메인은 답변이 전문가 조언을 대신하지 않는다는 안내를 표시한다.

확인
- 문서 수집과 답변 생성 중 진행 상태가 표시된다.
- 색인이 없는 상태, API 키가 없는 상태로 실행해 안내가 표시된다.
- 답변에 전문가 조언을 대신하지 않는다는 안내가 표시된다.

## 2. 기능 요구사항 — 심화 (F2013 ~ F2016, 선택)

| 번호 | 조건 | 확인 |
|---|---|---|
| F2013 프론트엔드 직접 구현 | HTML·CSS·JavaScript 로 화면 구현, 화면과 서버를 분리하고 요청·응답 형식 정의, 질문 입력·답변 표시·근거 표시 모두 제공 | 화면이 HTML·CSS·JS 로 동작하고 질문·답변·근거가 모두 표시된다 |
| F2014 MMR 검색 | 검색 결과를 넉넉히 가져온 뒤 다양성을 고려해 근거 선별(예: 30건 중 10건), 겹치는 청크가 몰리지 않음, 유사도 검색과 결과 차이를 확인할 수 있음 | 같은 질문에 유사도·MMR 을 각각 적용해 근거 목록 차이를 확인 |
| F2015 RAG 전후 품질 비교 | 대표 질문에 RAG 사용 전후 답변 확보, 사실 정확성·근거 제시 여부로 차이 정리, 비교 결과를 문서로 제출 | 대표 질문 5개 이상(근거 없이 답하면 틀리기 쉬운 질문), RAG 없이 1번·근거 붙여 1번 나란히 기록, 사실 정확성·근거 제시·모르는 것을 모른다고 답하는지 3기준 비교 |
| F2016 여러 문서 출처 결합 | 종류가 다른 문서 출처(예: 위키백과와 PDF)를 함께 색인, 근거에 출처 종류 구분 표시, 출처별로 수집·청킹 방식을 달리했다면 이유 설명 | 근거 목록에 출처 종류가 구분돼 표시된다 |

## 3. 비기능 요구사항 (NF2001 ~ NF2007)

| 번호 | 요구사항 | 확인 |
|---|---|---|
| NF2001 응답 시간 | 대표 질문의 전체 처리 시간이 사용에 지장이 없다 | 대표 질문 처리 시간 측정 |
| NF2002 수집 캐시 | 이미 수집·색인한 검색어는 다시 수집하지 않는다 | 같은 검색어 재수집이 일어나지 않는다 |
| NF2003 API 키 관리 | API 키는 환경변수로 관리하고 소스코드에 포함하지 않는다 | 소스코드·제출물에 API 키가 남아 있지 않다 |
| NF2004 내부 정보 비노출 | 화면에 API 키, 전체 프롬프트, 오류 추적 정보를 노출하지 않는다 | 화면에 해당 정보가 보이지 않는다 |
| NF2005 모듈 분리 | 수집·색인·검색·생성·UI 책임 분리, 도메인에 묶인 부분은 데이터 준비 영역에 모은다 | 모듈 분리 확인 |
| NF2006 외부 API 예절 | 재시도·호출 간격 규칙 준수, 출처가 요구하는 식별 정보(예: 위키백과 User-Agent 연락처) 포함 | 재시도·간격·식별 정보 확인 |
| NF2007 출처와 이용 조건 | 수집한 데이터·문서의 출처와 이용 조건을 기록하고 지킨다 | 기록 여부 확인 |

## 4. 제출물 (명세 6장 · 4.8)

| 산출물 | 포함할 내용 |
|---|---|
| 요구사항 정의서 | 필수·심화 요구사항 정리, 기능별 요구사항 표(F2001~), 도메인과 조건 충족 근거(항목 수, 문서 출처·이용 조건, 근거가 필요한 질문 예시) |
| RAG 파이프라인 설계문서 | 두 컬렉션 구조와 메타데이터 필드, 수집·청킹·색인 흐름, 병합·중복 제거 방식, 프롬프트 3개의 역할·출력 형식, 청크 크기·중복 길이·Top-k 를 정한 이유와 바꿨을 때 차이, 근거 표시 방식, 특화 기능 설계 이유, 선택 이유·겪은 문제·해결 과정 |
